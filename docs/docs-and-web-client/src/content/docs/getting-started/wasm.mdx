`transliterate_wasm` runs the 🦀 Rust implementation compiled to WebAssembly. It has the same API as `transliterate` and is about 2.5–4× faster. It is part of the `lipilekhika` package, no extra install needed.

## Usage

```typescript
import { transliterate_wasm } from 'lipilekhika';

await transliterate_wasm('na jAyatE mriyatE vA', 'Normal', 'Devanagari'); // न जायते म्रियते वा
await transliterate_wasm(['rAma', 'kRShNa'], 'Normal', 'Telugu'); // ['రామ', 'కృష్ణ']

// custom options, as with `transliterate`
await transliterate_wasm('गङ्गा', 'Devanagari', 'Gujarati', {
  'brahmic_to_brahmic:replace_pancham_varga_varna_with_anusvAra': true
}); // ગંગા
```

The module is loaded on the first call. To have it ready before then, call `preloadWasm()` at startup:

```typescript
import { preloadWasm } from 'lipilekhika';

await preloadWasm();
```

## Choosing an Entry Point

`transliterate_wasm` is available from three imports, which differ only in how the WASM module is loaded:

| Import | WASM module | Use for |
| --- | --- | --- |
| `lipilekhika` | Embedded (base64) in a chunk loaded on first use | **Recommended.** Node.js, Bun, Deno, browsers, any bundler or CDN, no setup |
| `lipilekhika/wasm` | Loaded the best way for the runtime (see below) | Cloudflare Workers and Vercel Edge (required there), and the separate `.wasm` file in browsers |
| `lipilekhika/wasm/slim` | Nothing embedded, you pass the `.wasm` file to `initWasm()` | A strict CSP, hosting the file yourself, or a setup the others do not cover |

<Aside type="tip">
  Use `lipilekhika` unless your code runs on Cloudflare Workers or Vercel Edge. To switch, change only the import path: the functions and their types are the same.
</Aside>

## Cloudflare Workers and Vercel Edge

These runtimes do not allow compiling WebAssembly from bytes, so the embedded module of `lipilekhika` can not load there (it throws an error pointing to `lipilekhika/wasm`). Use `lipilekhika/wasm`:

```typescript
import { transliterate_wasm } from 'lipilekhika/wasm';

export default {
  async fetch() {
    return new Response(await transliterate_wasm('namaskAra', 'Normal', 'Devanagari')); // नमस्कार
  }
};
```

`lipilekhika/wasm` picks its build through export conditions, with no configuration:

- **Cloudflare Workers** (`workerd`) — imports the `.wasm` file as a module. Works with `wrangler` and the Cloudflare Vite plugin (Astro, SvelteKit, React Router, Nuxt, ...), in dev and deployed.
- **Vercel Edge / Next.js edge** (`edge-light`) — imports the `.wasm` file with `?module`.
- **Browsers** (`browser`) — fetches the `.wasm` file, see below.
- **Node.js, Bun, Deno** — the embedded module, as `lipilekhika`.

So in a full stack app (eg. Astro on Cloudflare) the same import works on the server and in the browser.

### In the Browser

`lipilekhika/wasm` fetches the `.wasm` file from `new URL('../lipilekhika.wasm', import.meta.url)`: 80 KB gzipped instead of 114 KB of base64, cached on its own and compiled while it downloads. If the file can not be loaded, it falls back to the embedded module and logs a warning.

| Setup | Extra config |
| --- | --- |
| Vite 8 (Astro 7, SvelteKit, ...), dev and build | None |
| Vite 7 and older, build | None |
| Vite 7 and older, dev | `optimizeDeps: { exclude: ['lipilekhika'] }` in `vite.config`, else the embedded module is used |
| esbuild | Copy `node_modules/lipilekhika/dist/lipilekhika.wasm` to the folder above your bundle, else the embedded module is used |
| CDN, no bundler | None |

## Manual Loading (`lipilekhika/wasm/slim`)

Call `initWasm()` once with the `.wasm` file, exported as `lipilekhika/lipilekhika.wasm`. It takes a `WebAssembly.Module`, the bytes, a `Response`, or a URL to fetch (or a promise of one).

<Tabs>
  <TabItem label="Vite">
    ```typescript
    import { initWasm, transliterate_wasm } from 'lipilekhika/wasm/slim';
    import wasmUrl from 'lipilekhika/lipilekhika.wasm?url';

    await initWasm(wasmUrl);
    await transliterate_wasm('namaste', 'Normal', 'Devanagari');
    ```
  </TabItem>
  <TabItem label="Cloudflare Workers">
    ```typescript
    import { initWasm } from 'lipilekhika/wasm/slim';
    import wasmModule from 'lipilekhika/lipilekhika.wasm';

    await initWasm(wasmModule);
    ```
  </TabItem>
  <TabItem label="Vercel Edge">
    ```typescript
    import { initWasm } from 'lipilekhika/wasm/slim';
    import wasmModule from 'lipilekhika/lipilekhika.wasm?module';

    await initWasm(wasmModule);
    ```
  </TabItem>
  <TabItem label="Node.js">
    ```typescript
    import { readFile } from 'node:fs/promises';
    import { createRequire } from 'node:module';
    import { initWasm } from 'lipilekhika/wasm/slim';

    const require = createRequire(import.meta.url);
    await initWasm(await readFile(require.resolve('lipilekhika/lipilekhika.wasm')));
    ```
  </TabItem>
  <TabItem label="CDN">
    ```typescript
    import { initWasm } from 'lipilekhika/wasm/slim';

    // the version must match the installed package
    await initWasm(fetch('https://cdn.jsdelivr.net/npm/lipilekhika@1.0.14/dist/lipilekhika.wasm'));
    ```
  </TabItem>
</Tabs>

`slim` loads the same file as `lipilekhika/wasm`, so it is not smaller: use it to decide where the file comes from.

<Aside type="note">
  All three entries share one WASM instance: the first one used loads the module and the others reuse it. If it is already loaded, `initWasm()` loads nothing.
</Aside>

<Aside type="caution">
  **Content Security Policy:** WebAssembly in a browser needs `'wasm-unsafe-eval'` in `script-src`. `lipilekhika/wasm` and `slim` also fetch the `.wasm` file, so `connect-src` must allow its origin.
</Aside>

## Other Environments

```html
<!-- Browser, from a CDN -->
<script type="module">
  import { transliterate_wasm } from 'https://cdn.jsdelivr.net/npm/lipilekhika/dist/esm/index.mjs';
  console.log(await transliterate_wasm('namaste', 'Normal', 'Devanagari')); // नमस्ते
</script>
```

```typescript
// Deno
import { transliterate_wasm } from 'npm:lipilekhika';
```

```typescript
// Next.js edge route (app/api/transliterate/route.ts)
import { transliterate_wasm } from 'lipilekhika/wasm';

export const runtime = 'edge';

export async function GET() {
  return new Response(await transliterate_wasm('namaste', 'Normal', 'Devanagari'));
}
```

**Jest (jsdom):** jsdom lacks `TextEncoder` / `TextDecoder`, which the WASM bindings use. Add them in a setup file (`setupFiles`):

```javascript
const { TextEncoder, TextDecoder } = require('node:util');
Object.assign(globalThis, { TextEncoder, TextDecoder });
```

## API Reference

### `transliterate_wasm(text, from, to, options?)`

- `text: string | string[]` — one string or many (same options for all)
- `from`, `to: ScriptLangType` — script/language names
- `options?: TransliterationOptions` — custom transliteration options

**Returns:** `Promise<string | string[]>`, the same shape as `text`.

### `preloadWasm()`

Loads the WASM module ahead of the first call. **Returns:** `Promise<void>`.

### `initWasm(wasm)` (`lipilekhika/wasm/slim` only)

Loads the module from `wasm`: a `WebAssembly.Module`, bytes (`BufferSource`), a `Response`, a URL (`string | URL`), or a promise of one. Call it before `transliterate_wasm`; later calls return the same load. If it fails, it can be called again. **Returns:** `Promise<void>`.

## WASM or JavaScript?

In the benchmarks WASM transliterates the test corpus in 59 ms on Node.js and 47 ms on Bun, against 219 ms and 122 ms for `transliterate`.

<Aside type="tip" title="One load, every script ready">
  The WASM module contains the data of all scripts, so it is loaded once (one cold start) and after that any script pair is instant, including when the user switches scripts. `transliterate` instead loads each script's data on its first use, a separate fetch per script in the browser (see `preloadScriptData`).
</Aside>

- **WASM** — large texts, many or repeated calls, switching between many scripts, servers.
- **JavaScript** (`transliterate`) — a few small calls, where loading the module first is not worth it; environments without WebAssembly.

WebAssembly is supported by Chrome/Edge 57+, Firefox 52+, Safari 11+, Node.js, Deno and Bun. In very old browsers (IE11) use `transliterate`.
